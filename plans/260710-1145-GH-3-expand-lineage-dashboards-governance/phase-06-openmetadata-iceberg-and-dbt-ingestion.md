# Phase 6: OpenMetadata Iceberg and dbt ingestion

## Overview

Make OpenMetadata show a real catalog: (1) ingest the **physical Iceberg tables** published to Lakekeeper/MinIO via OpenMetadata's Iceberg connector, and (2) ingest **dbt artifacts** so the catalog also shows **logical dbt model lineage, descriptions, and tests** — not only physical tables. Resolve the resource conflict (Iceberg ingestion needs `lake` + `governance` up together) with an explicit, guarded, documented **host-side `make catalog-ingest` co-run window** — run with Airflow stopped — that keeps the 16GB machine safe. **This phase does not add any Airflow tasks or Airflow-image dependencies** (see Phase 5 / plan.md decision 1); ingestion is invoked from the host via the pinned `openmetadata/ingestion` tooling.

This phase depends on Phase 2 (dbt artifacts) and Phase 4 (published Iceberg tables), **not** on Phase 5: the Iceberg tables can be produced either by `make lake-publish` or by the DAG's `publish` group, and ingestion runs afterward with Airflow down.

## Requirements

- **Functional**
  - **Iceberg ingestion workflow:** add `governance/openmetadata/ingestion/iceberg_ingestion.yaml` using OpenMetadata's Iceberg connector with a **RestCatalog** pointing at Lakekeeper (`http://lakekeeper:8181/catalog` / host equivalent) and S3 fileIO pointing at MinIO. `serviceName` e.g. `retail_iceberg`. It crawls the ≥8 curated assets from Phase 4 into the catalog as physical tables. Credentials (MinIO keys, OM JWT) via env only.
  - **dbt artifact ingestion (existing, extend):** keep `dbt_ingestion.yaml`; ensure it points at the Phase-2 `target/manifest.json` + `catalog.json` (generated by `make dbt-docs`) so logical `stg_*`/`int_*`/`dim_*`/`fct_*`/`mart_*` lineage, descriptions, and tests land. Align its `serviceName` so dbt lineage attaches to the intended database service.
  - **Curated-asset reuse (required generator + check):** YAML cannot read `lake/curated_assets.json` directly, so add a **required** renderer `governance/openmetadata/ingestion/render_iceberg_ingestion.py` that reads `lake/curated_assets.json` (Phase 4) and writes `iceberg_ingestion.yaml`'s table filter from it. Add a verification step (run in `make catalog-ingest` and in P7) that re-renders and asserts the committed/used `iceberg_ingestion.yaml` table filter **matches** the curated list, failing loudly on drift. A "documented mapping" alone is not sufficient — the generated-vs-source match is enforced mechanically.
  - **Distinction documented:** `governance/openmetadata/README.md` explains DuckDB logical dbt models (logical lineage) vs published Iceberg physical assets (physical tables), and how the two views relate in the catalog.
  - **Verification step:** a host-side `governance/openmetadata/verify_catalog.py` (invoked by `make catalog-ingest` and the runbook — **not** an Airflow callable) queries the OpenMetadata API for the ingested Iceberg service + dbt lineage and prints a summary (counts of tables, lineage edges) as evidence (AC7/AC8).

- **Non-functional — resource-safe co-run window (R2):**
  - By default the Makefile still refuses `lake` + `governance` together. Add an **explicit opt-in** path (e.g. `make catalog-ingest FORCE_COLOCATE=1`, or a dedicated target that internally sets the override) that:
    1. Stops Airflow (`make down` of orchestration) and any heavy generation.
    2. Starts `lake` (MinIO + Lakekeeper) and `governance` (OpenMetadata) together **only** for the ingestion window.
    3. Runs Iceberg ingestion, then dbt ingestion, then `verify_catalog`.
    4. Tears down `lake` (keeps governance if the user wants to browse, or tears both down).
  - Documented memory budget for the window (approx): OpenMetadata server 2g + ES 1g + MySQL 1g (~4g) + Lakekeeper 1g + lakekeeper-db 0.5g + MinIO 1g (~2.5g) + ingestion python ~0.5g ≈ **~7g of container limits + Docker/macOS overhead ≈ ~11g peak** — fits 16GB only if Airflow and heavy generation are **not** running. The window enforces that by stopping them first.
  - Keep OM footprint minimal (ES `-Xms512m -Xmx512m` already set; do not raise).

## Architecture

```text
                 ┌─────────────── OpenMetadata (governance) ───────────────┐
Lakekeeper REST ─┤  Iceberg connector (RestCatalog + MinIO fileIO)         │
  + MinIO (lake) │     → physical tables: retail_iceberg.retail.<asset>    │
                 │  dbt connector (manifest.json + catalog.json)           │
dbt target/ ─────┤     → logical models + lineage + descriptions + tests   │
                 └──────────────────────────────────────────────────────── ┘
                         verify_catalog → API summary (evidence)
```

Two services in the catalog: a physical Iceberg service (`retail_iceberg`) and the logical dbt-sourced service. Document how a mart appears in both views.

## Implementation Steps

1. **Compatibility gate (do this first, before dependent work).** Spike the OpenMetadata 1.6.5 Iceberg connector against the pinned Lakekeeper v0.13.1 + MinIO: pin the exact `openmetadata-ingestion` extras, prove a minimal RestCatalog + S3 fileIO ingestion reaches Lakekeeper and lists at least one curated table. Record the outcome in `versions.md`. **If it fails:** either pin-bump (if safe) or invoke the documented fallback (dbt-artifact-only logical lineage) and flag to the auditor that AC7's physical-Iceberg half is at risk — do not proceed to build the full Iceberg workflow on an unproven connector.
2. Add the required renderer `render_iceberg_ingestion.py` that reads `lake/curated_assets.json` and writes `iceberg_ingestion.yaml`'s table filter; add the re-render match-check.
3. Author `iceberg_ingestion.yaml` (RestCatalog → Lakekeeper, S3 fileIO → MinIO), env-templated credentials, table filter produced by the renderer.
4. Align `dbt_ingestion.yaml` with the Phase-2 artifacts and serviceName.
5. Add the host-side `verify_catalog.py` API summary check.
6. Add the guarded `make catalog-ingest` target that stops Airflow/gen, starts lake+governance, runs the renderer match-check, both ingestions, then `verify_catalog`, then tears down lake.
7. Run the window end-to-end; capture both ingestion summaries + `verify_catalog` output as evidence (AC7/AC8). Tear down.

## Success Criteria

- [ ] Compatibility gate (step 1) passed: OM 1.6.5 Iceberg connector proven against Lakekeeper v0.13.1 + MinIO, outcome recorded in `versions.md` **before** the full workflow is built (or fallback taken and flagged).
- [ ] `render_iceberg_ingestion.py` match-check passes: `iceberg_ingestion.yaml` table filter equals `lake/curated_assets.json` (fails loudly on drift).
- [ ] Iceberg ingestion completes; catalog shows the ≥8 curated physical Iceberg tables (AC7).
- [ ] dbt ingestion completes; catalog shows logical `stg/int/core/mart` lineage + descriptions + tests (AC7).
- [ ] `verify_catalog` prints a non-empty summary (table + lineage counts) captured as evidence (AC8).
- [ ] The co-run window is opt-in, guarded, and documented with memory math + teardown; default guard still refuses accidental co-run (R2).
- [ ] No JWT/MinIO credentials committed; env-only (AC9).
- [ ] `versions.md` records the Iceberg-connector validation outcome (or documented fallback).

## Risk Assessment

- **R2 (co-run memory):** window stops Airflow + heavy gen first; documented ~11g peak; teardown lake after. If the machine is under pressure, tear down governance too before resuming other work.
- **R3 (connector version drift):** validate early; if OM 1.6.5 Iceberg connector can't reach Lakekeeper v0.13.1 cleanly, fallback is dbt-artifact-only logical lineage + a documented note that Iceberg physical ingestion needs a version bump — flagged to the auditor since it would partially miss AC7. Preferred outcome: validated Iceberg ingestion.
- **Rollback:** revert ingestion configs / verify script / Makefile target; delete the OM services in the UI; `make down`; Docker volumes ignored/removable.
